# 無料相談の予約設定（Google カレンダー予約スケジュール → `/consult`）

相談予約導線を Tally フォームから **Google カレンダーの予約スケジュール** に切り替えました。
`/consult` に予約カレンダーを iframe で埋め込み、ページ遷移させず自社ドメイン内で予約が完結します。

- 相談は **15分・オンライン（Google Meet）**。Meet リンクは予約スケジュールが自動発行します。
- 予約を最優先とし、事前ヒアリングのフォームは置きません。質問は予約完了後の自動メールで任意回答としてもらいます。

---

## 1. Google カレンダー予約スケジュールの作成

1. Google カレンダー →「予約スケジュール」を作成
   - **名称**：Workle 無料相談（15分）
   - **予約枠**：15分 / 予約間の余白：15分 / 受付可能期間：今日から30日先まで
   - **対応可能時間**：平日 10:00〜19:00（実運用に合わせて調整）
   - **直前予約の制限**：開始 **2時間前まで**（準備時間の確保）
   - **会議形式**：**Google Meet**（自動発行）
2. 予約フォームの項目（Workspace プランで追加質問が使える場合のみ）
   - 氏名・メールアドレス（標準）
   - 追加質問：「ご興味のあるサービス（リサーチ / 営業代行 / SNS運用 / 未定）」
   - 追加質問：「サービスのURL（あれば）」
   - ※追加質問が使えないプランの場合は設定不要。下記「4. 予約完了後のフォロー」の自動メールで代替します。
3. **確認メール・リマインダーを ON** にする
4. 「共有」→ **埋め込みコード**（「ウェブサイトに埋め込む」）を取得し、iframe の `src` に使う URL を控える

> ⚠️ **重要：共有用の短縮リンク（`https://calendar.app.google/xxxx`）は iframe 埋め込みできません。**
> 短縮リンク・通常の予約ページURLは Google 側が `X-Frame-Options: SAMEORIGIN` を返すため「接続が拒否されました」になります。
> 埋め込みに使えるのは「埋め込みコード」内の次の形式だけです：
> `https://calendar.google.com/calendar/appointments/schedules/{スケジュールID}?gv=true`
> （`?gv=true` が付いた `calendar.google.com/calendar/...` 形式。これを `NEXT_PUBLIC_BOOKING_URL` に設定します）

## 2. 環境変数の設定 `NEXT_PUBLIC_BOOKING_URL`

予約 URL は **ハードコードせず** 環境変数で参照しています。
`app/consult/page.tsx` が `process.env.NEXT_PUBLIC_BOOKING_URL` を読み、`app/consult/ConsultBooking.tsx` の iframe に渡します。

```bash
# .env.local（ローカル）— 必ず ?gv=true の埋め込み用URLを使う（短縮リンク不可）
NEXT_PUBLIC_BOOKING_URL=https://calendar.google.com/calendar/appointments/schedules/xxxxxxxx?gv=true
```

本番（Vercel）では次で登録します。

```bash
vercel env add NEXT_PUBLIC_BOOKING_URL production
# 値に上記の予約スケジュール URL を貼り付け
```

- `NEXT_PUBLIC_` 接頭辞のため **クライアントにバンドルされます**（= 公開情報）。予約 URL は公開して問題ないため OK。
- 未設定でも動くよう、コード側に現行 URL のフォールバックを置いています（`app/consult/page.tsx`）。恒久運用では env を必ず設定してください。
- 変更後は再デプロイ（またはローカルは dev サーバー再起動）で反映されます。

## 3. `/consult` ページの構成（実装済み）

- ヘッダー：ロゴ +「他のサービス」+「無料相談を予約」（全ページ共通の `SiteNav`）
- 巨大英語見出し「BOOK IT.」+ 日本語「無料相談のご予約」
- リード文（費用・契約なし / 内容未定でも可）
- **予約カレンダーの埋め込み（ページの主役・ファーストビュー内）**
  - 白背景カード（2px `#111` ボーダー・角丸16px）
  - PC 700px / モバイル 620px・横幅いっぱい
  - 読み込み中はスケルトン表示
  - iframe が表示できない環境向けに直リンクのフォールバック
- カレンダー下に補足3点（15分/オンライン・費用契約なし・準備不要）
- 最下部に「まず資料を見たい方へ」→ サンプルレポートのモーダル

## 4. 予約完了後のフォロー（1通だけ手動 or 自動送信）

予約フォームでは何も聞かない（または追加質問2つまで）。予約完了後、Workle 側から次の1通を送ります。

**件名：** 【Workle】ご予約ありがとうございます（当日の進め方）

**本文：**

```
このたびはご予約ありがとうございます。

▼ ご予約内容
・日時：{{予約日時}}
・オンライン（Google Meet）：{{Meetリンク}}

当日は15分で、
　① 現在の状況
　② お困りごと
　③ Workleでできること
をお話しします。

事前にお答えいただけると当日が早く進みます（任意）：
　・サービスのURL
　・今、一番困っていること
　・ご検討中のサービス（リサーチ / 営業代行 / SNS運用）

ご返信がなくても問題ありません。当日うかがいます。

— Workle
support@workle-kle.com
```

## 5. 計測（GA4）

`/consult` では次のイベントを送信します（`app/consult/ConsultBooking.tsx`）。

| イベント名 | タイミング |
| --- | --- |
| `consult_page_view` | `/consult` 表示時 |
| `consult_iframe_loaded` | 予約カレンダー iframe の読み込み完了時 |

- **予約完了イベントは iframe 内（Google 側）のため計測できません。** 予約数は **Google カレンダー側で確認** してください。
- 既存の `consult_click`（各ページの相談 CTA クリック）も引き続き送信されます。

## 6. Tally からの移行メモ

- サイト全体の「無料相談」CTA は `/consult` に統一しました（ヘッダー・料金・各 LP・サンプルモーダル・フッター・サンプル請求メール）。
- 相談用の Tally フォーム（`Workle - 無料相談のお申し込み`）への直リンクは撤去済み。相談用の専用環境変数は元々なく（URL はハードコードされていた）、削除対象はありませんでした。
- **入稿フォーム（決済後の案件情報入力）は別物** です。`NEXT_PUBLIC_TALLY_INTAKE_URL` を使う `app/test/thanks`・`app/test/status`・Stripe Webhook・注文確認メールはそのまま残しています（今回の変更対象外）。
